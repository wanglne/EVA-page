      <h3>Safety alignment through model editing.</h3>
      <p>Jailbreaks can exploit both textual and visual inputs. <strong>EVA treats safety alignment as a targeted model editing task</strong>: it identifies harmful key representations, optimizes safe target values, and updates selected MLP weights. The framework applies to both LLMs and VLMs, with regularization to limit changes on benign inputs.</p>
      <p>Experiments show reduced jailbreak success with largely retained utility across text and multimodal benchmarks.</p>

<Wide maxWidth="70rem">
  <div className="overview-heading">
    <div>
      <h2 id="overview-title">Overview</h2>
      <h3>Where does EVA fit?</h3>
    </div>
    <p>EVA applies safety edits during downstream adaptation, after foundational alignment. The updated weights are then deployed in place of the original weights.</p>
  </div>
  <OverviewFigure />
  <div className="overview-rationale">
    <h3>Why Use Targeted Model Editing After Release?</h3>
    <p>A released model can encounter jailbreaks that its initial safety alignment did not anticipate. Broad safety fine-tuning can alter useful capabilities, while external defenses add components to the inference pipeline. EVA instead uses localized parameter edits to modify the model's response to harmful concepts without adding inference-time defense components.</p>
  </div>
</Wide>

</section>

      <h3>How Does EVA Edit a Model?</h3>
    </div>
    <PaperFigure name="method" alt="EVA editing pipeline: extract harmful text tokens, generate query variations, select related image tokens through attention, aggregate representative keys, optimize safe values, and update MLP down-projection weights." />
    <p>Together, these steps incorporate targeted safety corrections directly into the model weights. Once editing is complete, the updated model can be deployed without an additional inference-time defense module.</p>
